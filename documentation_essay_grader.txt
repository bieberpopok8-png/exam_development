Neuroradiology AI Exam Grader
An enterprise-grade, AI-assisted application designed to grade medical essay exams (specifically Neuroradiology) using local LLMs. The system reads typed or scanned student answers, visually extracts structured rubrics, and grades the answers semantically, providing professors with an auditable, side-by-side comparison interface.

Project Overview
Grading medical essay exams is a time-consuming process prone to human fatigue. This application acts as an intelligent Teaching Assistant.

Instead of trusting a "black box" AI to give a score, the system enforces a Human-in-the-Loop workflow. The AI reads the student's text, reads the professor's rubric, and maps the student's exact sentences to the rubric criteria. The professor is presented with a split-screen view: the student's answer (with AI highlights) and a rubric table (with suggested points and AI reasoning). The professor can accept, override, or adjust the AI's score with a single click.

Tech Stack
Frontend & Backend: Next.js 16 (App Router) with TypeScript
Styling: Tailwind CSS + Shadcn UI
Database: PostgreSQL
ORM: Prisma (v6)
AI Engine: Ollama (Running qwen3-vl:4b-instruct locally)
Package Manager: npm / bun
System Architecture
The application runs entirely locally, ensuring patient data and academic integrity are never sent to the cloud.

Next.js API Routes handle file uploads, database queries, and AI orchestration.
Ollama runs on the local machine, hosting the Vision-Language model.
PostgreSQL stores exam metadata, structured rubric JSON, and extracted student text.
The AI Pipeline
The grading process is split into a strict, multi-phase pipeline to maximize accuracy and prevent AI hallucinations.

Phase 1: Rubric Ingestion (Vision)
Professors upload rubric files (PDF, PPTX, or Images). The backend converts these files to PNG images and sends them to Qwen-VL. The AI is prompted to extract all criteria into a structured JSON array ([{id, criterion, points}]). This JSON is stored in the database.

Phase 2: Student Answer OCR (Vision)
Professors upload student answer PDFs. Qwen-VL visually reads the documents and extracts the raw text. This text is saved to the database, completely decoupling the slow OCR process from the grading step.

Phase 3: Semantic Grading (Text Comparison)
When the professor clicks "Grade", the backend sends the Rubric JSON and the Student Text to Qwen-VL.

Strict Prompting: The AI is instructed to act as a "strict, pedantic medical professor."
Semantic Matching: It checks if the student captured the medical concept, but enforces partial credit if specific qualifiers (e.g., "hiperdens") are missing.
Quote Extraction: It extracts the exact verbatim quote from the student's text that proves they earned the points.
Validation: The backend validates the AI's output to ensure 1-to-1 ID mapping (no skipped rubric items) and caps awarded points at the maximum allowed.
Database Schema
The application uses Prisma with PostgreSQL. The core schema is designed around JSON storage for AI flexibility:

prisma

model Exam {
  id        Int       @id @default(autoincrement())
  title     String
  createdAt DateTime  @default(now())
  questions Question[]
}

model Question {
  id          Int      @id @default(autoincrement())
  examId      Int
  text        String?
  rubricData  Json?    // Stores the AI-extracted rubric [{id, criterion, points}]
  answers     Answer[]
  
  exam        Exam     @relation(fields: [examId], references: [id], onDelete: Cascade)
}

model Answer {
  id          Int      @id @default(autoincrement())
  questionId  Int
  studentName String
  fileUrl     String?  // Path to original PDF if saved locally
  ocrText     String?  // Text extracted by Qwen-VL
  gradeData   Json?    // AI grading result [{id, awarded_points, quote, explanation}]
  totalScore  Int?     // Final calculated score
  
  question    Question @relation(fields: [questionId], references: [id], onDelete: Cascade)
}
UI/UX Design
Built with Tailwind CSS and Shadcn UI, the interface is designed to feel like a premium macOS application.

Glassmorphism: Frosted glass cards, subtle shadows, and blurred backgrounds.
Expandable Pill Rows: Questions are displayed as long pills. Clicking the pill expands a detailed rubric table below it.
File Upload Triggers: Clicking the "Upload" text inside a pill triggers the OS file explorer, strictly filtering for .pdf, .png, .jpg, .jpeg, .docx, .txt, .csv.
Split-Screen Grading: The student's OCR text on the left, the AI-mapped rubric table on the right. Hovering over a rubric item highlights the corresponding quote in the student's text.
Getting Started (Installation)
Prerequisites
Node.js (v18+)
PostgreSQL database
Ollama installed and running
1. Clone and Install Dependencies
bash

npm install
2. Set up Environment Variables
Create a .env file in the root directory:

env

DATABASE_URL="postgresql://postgres:your_password@localhost:5432/exam_grader?schema=public"
3. Set up the Database
Run the Prisma migration to create your tables:

bash

npx prisma db push
npx prisma generate
4. Download the AI Model
Open a terminal and pull the Vision-Language model:

bash

ollama pull qwen3-vl:4b-instruct
5. Run the Application
bash

npm run dev
Visit http://localhost:3000 to start grading!

Future Roadmap
Multi-Question PDF Splitting: Automatically detect Question # headers in a 16-page student PDF and split them into individual database rows before grading.
PPTX Image Extraction: Fully implement LibreOffice or python-pptx integration to extract images from PowerPoint rubrics for Vision AI processing.
Self-Consistency Checks: Run the grading step twice in the background. If the scores disagree by more than 10 points, flag the exam for mandatory human review.
